# 地图求解与点击

## 流程

脚本从本机 Reqable MCP 读取最新的 map_info_ex，解压 match_data，核对静态地图，运行求解器并独立回放。牌型完全使用地图中的 type。点击坐标由地图坐标和固定窗口布局换算，不识别截图中的牌面。

需先在游戏内进入第二关，保持初始棋盘和空槽位。程序不会自动登录微信、点击首页入口、观看广告或使用道具。

## 使用

推荐流程：打开 Reqable 并开始抓包，在微信进入第二关的初始地图，然后在项目目录执行：

```sh
python run
```

该命令自动使用项目虚拟环境，读取最新地图、求解、检查当前窗口并执行完整点击序列。运行期间不要手动操作游戏或移动鼠标；移动鼠标或按 Ctrl-C 可停止。

仅读取地图、求解和核验窗口，不点击：

```sh
scripts/run_game.command
```

限制实际点击步数，用于小步试跑：

```sh
scripts/run_game.command --execute --max-clicks 4
```

按输出的 runDirectory 恢复，继续剩余点击：

```sh
scripts/run_game.command --resume /path/to/runs/your-run-id --execute
```

从新开局直接执行完整方案：

```sh
scripts/run_game.command --execute
```

保持游戏窗口位置和尺寸不变，并等待鼠标自动操作。点击间隔默认 0.5 秒，允许设置为 0.3 秒以上。日志中的槽位是根据地图 type 和解法步骤计算出的预期内容，不是从游戏画面读取的实测槽位。type 1 按“草”显示。

## 停止与记录

移动鼠标超过 3 个屏幕逻辑单位、终端按 Ctrl-C，或在本次运行目录创建 STOP 文件，均可停止。窗口失去焦点、被其他窗口遮住、位置或尺寸改变、出现新的开局记录时，也会停止。

每次运行保存在独立 runs 目录，包含 map.json、solution.json、coordinate-model.json、preflight.json 和 progress.json。抓包会话凭据不写入这些文件。

progress.json 的 nextStep 表示已通过画面核验的点击数。inFlight 为 true 时，表示有一次点击尚未确认，脚本拒绝自动恢复，避免重复点击。恢复只适用于同一局、上次点击已确认且没有额外手动操作的情况。

## 权限与环境

需要 Reqable 正在抓包，以及 macOS 的辅助功能权限。辅助功能权限须由用户在“系统设置 → 隐私与安全 → 辅助功能”中为启动脚本的应用开启：从终端启动时检查终端，从 Codex 启动时检查 Codex。脚本只检查权限，不修改系统权限。

Python 环境安装在项目 .venv，依赖列于 scripts/requirements-click.txt。窗口助手由 game_window.swift 编译，启动器会在源码更新后重新编译。

## 执行边界

脚本不会读取屏幕来确认点击结果、牌面或槽位。点击位置按 350×665 逻辑窗口的已知布局计算，再按实际窗口尺寸缩放。窗口比例不符合支持的布局时会停止。自动点击只代表按地图步骤发送了点击事件，不证明游戏已消除牌或服务端判定通关；最后完成后 `winScreenConfirmed` 保持 false。
