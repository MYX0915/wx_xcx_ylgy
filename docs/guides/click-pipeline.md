# 地图求解与点击

本页补充主流程的操作边界。安装、接口、命令参数和完整错误处理以 [主页 README](../../README.md) 为准。

## 前置条件

- Reqable 正在抓包，微信小游戏停在普通关卡或羊羊大世界的初始地图。
- 槽位为空，当前棋局尚未手动操作。
- 大世界若响应要求 seed，Reqable 历史记录中必须有可验证的同会话、同加密版本结算样本；否则流程会停止。
- 微信游戏窗口大小和位置符合当前支持的固定布局。
- 启动脚本的终端应用或 Codex 已获得 macOS 辅助功能权限。

## 运行方式

完整自动点击流程：

```sh
python run
```

只捕获地图、求解并预检，不发送点击：

```sh
scripts/run_game.command
```

显式开启点击并限制本次最多点击 4 张：

```sh
scripts/run_game.command --execute --max-clicks 4
```

根目录 `run` 自动启用 `--execute`；底层 `scripts/run_game.command` 默认只预检。

程序根据最新开始请求的路径和 `matchType` 识别模式：普通关卡使用 `map_info_ex` / `3`，大世界使用 `world/game_start` / `6`。普通关卡优先从 `match_data` 取牌型；大世界没有该字段时从 Reqable 捕获的 seed 响应恢复。大世界当前不使用普通关卡的牌名映射，日志中的牌型以数字显示。

地图读取和 seed 恢复成功后，仍须由求解器找到并独立验证完整步骤才会进入点击阶段。默认搜索时限为 120 秒；超时会停止而不会点击。已核验的一个大世界样本有 255 张牌，该样本曾在默认时限内求解超时。

## 点击与进度

每次运行在本机 `runs/` 下创建独立目录，保存地图、解法、坐标模型、预检和进度。日志槽位由已求出的步骤模拟得出，不是对游戏画面的实时读取。

发送一次点击前，程序先将 `inFlight` 写为 `true`；鼠标事件发送后再更新 `nextStep` 并清除 `inFlight`。因此：

- `nextStep` 表示已经发送且写入进度的点击数，不代表游戏或服务端已确认消除。
- 若 `inFlight` 仍为 `true`，上次点击结果有歧义，程序会拒绝自动续跑；先检查实际游戏画面。
- 完成全部计划只表示点击序列已发送。程序不识别胜利弹窗，也不会把 `winScreenConfirmed` 设为 `true`。
- 中断后只能对同一局、同一地图和未被手动操作的状态使用对应 `runs/` 目录续跑。新开局必须重新捕获并求解。

执行中按 Ctrl-C、移动鼠标或在运行目录创建 `STOP` 文件可请求停止。窗口被移动、尺寸改变、微信进程变化、Reqable 记录切换时也会终止本次点击流程。

## 坐标模型

当前点击器将游戏逻辑坐标映射到固定窗口布局，再按窗口缩放：

```text
screen_x = window_origin_x + (50 + 4.5 * colNum) * scale_x
screen_y = window_origin_y + (146 + 4.5 * rowNum) * scale_y
```

基准窗口尺寸为 350 × 665。比例不符合当前布局时会拒绝点击。点击坐标不来自截图识别；不要在运行期间调整窗口或手动操作游戏。
