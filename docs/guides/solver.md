# 地图求解器

主页 README 的“算法与规则”一节说明完整自动流程；本页记录求解器输入契约、规则和验证方法。

## 输入与运行

求解器读取包含 `levelData` 的地图 JSON。每张牌须提供唯一 `id`、正整数 `type`、逻辑坐标 `rolNum`、`rowNum` 和 `layerNum`；每种 `type` 的牌数必须是 3 的倍数。`typeName` 只用于输出显示，不参与求解。

```sh
python3 scripts/solve_map.py path/to/map-with-types.json \
  --seconds 120 \
  --output path/to/solution.json
```

输入地图必须对应当前棋局、初始空槽位且牌型不变。重新开局、洗牌或按不同顺序操作后，旧解法不再有效。求解器拒绝非棋盘 `AreaType` 和非零 `metaType`，不模拟动态特殊牌或道具。

## 游戏规则

- 每张牌占 8 个逻辑坐标单位。任意更高层的剩余牌与当前牌横向距离小于 8 且纵向距离小于 8 时，当前牌被遮挡；恰好相隔 8 不遮挡。
- 遮挡检查包含所有更高层，不仅是相邻层。牌堆按节点层数和坐标处理。
- 点击的牌进入容量为 7 的槽位；同类型累计 3 张立即消除。
- 第 7 张可以完成三消；若仍有 7 张未消除牌则该分支失败。
- 棋盘和槽位均为空时，方案成功。

## 搜索与验证

求解先运行最多 2 秒的正向深度优先搜索，使用启发式候选排序、失败状态缓存和有界重启。未找到解时，在剩余时间内使用 C++ 逆向束搜索。原生助手由 `scripts/reverse_search.py` 按需编译，需要 `clang++` 或兼容 C++17 的 `c++`。

逆向搜索从棋盘和槽位均为空的终局开始，逐步还原牌。只有该牌遮挡的所有下层牌均已还原，才允许还原它。逆向撤销一次三消会让槽位增加两张同类牌，其他逆向操作会减少一张；每个稳定状态仍要求槽位最多六张。最终将逆向路径倒序，得到实际点击顺序。

每一深度最多保留 10000 个不同局面，按依赖牌数量和槽内牌完成配对的距离排序。相同剩余牌集合的槽位计数由类型数量模三唯一确定，可以合并；启发式排序只影响搜索效率，不改变合法操作规则。

求解成功后，独立正向回放器逐步检查遮挡、重复点击、槽位容量、三消和终局。回放器直接检查坐标和实际槽位列表，不复用搜索器的遮挡位集合。`solved` 表示回放通过；`unsatisfiable` 只在未裁剪的完整搜索结束后报告；超出时间上限为 `timeout`，裁剪后候选耗尽为 `search_exhausted`，后二者均不等于无解。未找到完整解时不会点击。

## 测试

从项目根目录运行：

```sh
python3 -m unittest discover -s tests -v
```

求解器测试覆盖遮挡边界、跨层遮挡、槽位容量、三消、重复点击、超时和裁剪语义。逆向算法与四、五种牌型的小棋盘穷举结果交叉验证，并使用只含类型、坐标和层数的 255 张牌样本检查完整正向回放。
