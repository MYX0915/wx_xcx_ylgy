# 地图数据来源与字段核验

本文补充地图类型和坐标的来源。现行接口字段、解码方式及静态 `.map` 结构以主页 README 的“服务接口”为准。

## 当前数据来源

普通关卡每张牌的数字类型和运行时位置来自 `map_info_ex` 响应中的 `data.match_data`。羊羊大世界由 `world/game_start` 开始；当响应要求 seed 且没有 `match_data` 时，逐牌类型由捕获的 `/map_info_ex_seed` 响应恢复，再依据静态地图和 seed 生成。解析器按开始请求路径及 `matchType` 区分模式，避免用旧普通关卡响应代替大世界数据。

静态 `.map` 主要提供关卡几何结构、层数、节点坐标和 `blockTypeData` 类型总数。它本身不保证包含每个节点已经洗牌后的 `type`。普通关卡以 `match_data` 作为逐牌类型来源；大世界以已验证 seed 和实现中的生成算法作为来源。程序不以静态类型计数推测单张牌面，也不以截图分类替代数字 `type`。

## 字段对应

| 运行时字段 | 静态地图字段 | 用途 |
| --- | --- | --- |
| `layerNum` | `layerNum` | 所在层 |
| `colNum` | `rolNum` | 横向逻辑坐标 |
| `rowNum` | `rowNum` | 纵向逻辑坐标 |
| `moldType` | `moldType` | 节点结构属性的逐节点一致性检查 |
| `type` | 节点 `type=0` 待分配，`type=17` 为固定闪电；`blockTypeData` 为随机牌池组数 | 最终类型计数为随机牌池计数加固定闪电计数 |
| `blockId` | 无 | 运行时方块编号，写入合并后的 `cardId` |

`metaType`、`metaData` 和 `AreaType` 描述特殊牌或区域属性。支持初始棋盘的普通牌，以及有效 `goldBlockData` 配置下的闪电能量属性。其他动态属性或非棋盘区域仍会停止。

`goldBlockData` 来自静态地图 protobuf 字段 6，包括 `collectCount` 和 `blockList`。据此识别“闪电飞碟局”；无有效飞碟配置时，根据开始接口区分“普通局”和“大世界普通局”。地图类型与接口模式分别保存，避免改变名称表和坐标配置。

## 校验要求

合并运行时记录或按 seed 生成牌型时，至少检查：

- 每个 `(layerNum, colNum, rowNum)` 节点恰好匹配一次，无缺失或重复。
- `blockId` 唯一，`moldType` 与静态节点一致。
- 每张牌的 `type` 是正整数，且按 `blockTypeData` 各类型组数乘以 3、加上固定闪电数量校验。
- 固定闪电不消耗随机牌池，保留位置与类型；运行时合并也必须保持这些位置的 `type=17`。飞碟局另行模拟能量、随机移除和剩余棋盘，不能只按普通三消回放。
- `fullSync` 表示完整状态；新开局预检还须确认没有已消除或移动的牌。
- 普通关卡的 `match_data` 状态完整，或大世界 seed 响应与当前开始请求、同会话结算记录及加密版本均能通过校验。
- 数据缺失、解压失败、状态不完整或 seed 无法验证时停止，不回退到旧局数据或猜测牌型。
- 大世界 type ID 不直接套用普通关卡的显示名称表；名称映射需按模式单独核验。

## 样本快照

以下为 2026-10-08 核验的单局样本，具体牌数和类型分布不应视为所有日期的固定值：

- `levelKey`：900081。
- 第二关有 243 张牌、23 层、15 种数字类型。
- 类型计数为 `blockTypeData` 每种组数乘以 3；合计 81 组三消。
- 逐节点运行时坐标与静态地图完全匹配，未发现重复 `blockId` 或 `moldType` 不一致。
- 截图核对了部分可见牌；被遮挡牌的类型依据接口数据，不代表每一张都通过截图视觉核验。
- 用户确认 type 1 的显示名称为“草”。

同日核对的一个大世界样本包含 255 张牌、26 层、15 种数字类型和 43 张初始可点牌。逆向搜索约 18 秒得到完整解；实际点击完成后，结算请求为 `rank_state=1`、`removed=255`，响应 `err_code=0` 且 `game_over_resp.win=true`。该单局完成了解析、求解、点击与结算验证，不代表任意后续地图都能通关。

逐层牌面和该样本解法分别见 [样本目录](../samples/2026-10-08/)。Reqable 响应及解码后的 JSON 位于本机 `captures/`、`decoded/` 目录，因包含会话关联信息而不纳入仓库。
