# 地图数据来源与字段核验

本文补充地图类型和坐标的来源。现行接口字段、解码方式及静态 `.map` 结构以主页 README 的“服务接口”为准。

## 当前数据来源

每张牌的数字类型和运行时位置来自 `map_info_ex` 响应中的 `data.match_data`。解压后，第二关状态位于数组下标 1；逐牌记录位于 `gameState.allBlockRuntimeData`。当前解析器将运行时记录与静态地图节点按层和坐标合并，并校验节点集合、`moldType` 和牌型数量。

静态 `.map` 主要提供关卡几何结构、层数、节点坐标和 `blockTypeData` 类型总数。它本身不保证包含每个节点已经洗牌后的 `type`。程序不以静态类型计数推测单张牌面，也不以截图分类替代接口中的数字 `type`。

## 字段对应

| 运行时字段 | 静态地图字段 | 用途 |
| --- | --- | --- |
| `layerNum` | `layerNum` | 所在层 |
| `colNum` | `rolNum` | 横向逻辑坐标 |
| `rowNum` | `rowNum` | 纵向逻辑坐标 |
| `moldType` | `moldType` | 节点结构属性的逐节点一致性检查 |
| `type` | 无逐牌对应字段；`blockTypeData` 仅统计各类型数量 | 运行时实际牌型；数量乘以 3 后与静态地图计数交叉校验 |
| `blockId` | 无 | 运行时方块编号，写入合并后的 `cardId` |

`metaType`、`metaData` 和 `AreaType` 描述特殊牌或区域属性。当前求解器只支持棋盘区域和静态牌；遇到不支持的值时会停止。

## 校验要求

将运行时记录合并到静态地图时，至少检查：

- 每个 `(layerNum, colNum, rowNum)` 节点恰好匹配一次，无缺失或重复。
- `blockId` 唯一，`moldType` 与静态节点一致。
- 每张牌的 `type` 是正整数，且按 `blockTypeData` 计数校验。
- `fullSync` 表示完整状态；新开局预检还须确认没有已消除或移动的牌。
- `match_data` 为空、解压失败或状态不完整时停止，不回退到旧局数据或猜测牌型。

## 样本快照

以下为 2026-10-08 核验的单局样本，具体牌数和类型分布不应视为所有日期的固定值：

- `levelKey`：900081。
- 第二关有 243 张牌、23 层、15 种数字类型。
- 类型计数为 `blockTypeData` 每种组数乘以 3；合计 81 组三消。
- 逐节点运行时坐标与静态地图完全匹配，未发现重复 `blockId` 或 `moldType` 不一致。
- 截图核对了部分可见牌；被遮挡牌的类型依据接口数据，不代表每一张都通过截图视觉核验。
- 用户确认 type 1 的显示名称为“草”。

逐层牌面和该样本解法分别见 [样本目录](../samples/2026-10-08/)。Reqable 响应及解码后的 JSON 位于本机 `captures/`、`decoded/` 目录，因包含会话关联信息而不纳入仓库。
