# 大世界移动与周边地图

本功能读取羊羊大世界的地区地图，包括当前位置和邻近地块。消除关卡的卡牌坐标与本功能无关。

## 使用

保持 Reqable 捕获开启，再进入羊羊大世界的地区地图。在项目目录运行：

```bash
python3 scripts/world_snapshot.py --output runs/world-current.json
```

脚本从微信最近一条 `/gateway/ws` 连接中读取初始化消息、移动请求、移动回包和附近礼物推送，输出当前界面坐标、导航候选与动态避让原因。每次在游戏中移动并到达后重新运行，即可获取新的周边地块。加上 `--json` 可在终端输出完整 JSON。

连接选择先按域名、微信应用和 GET 方法筛选，再按记录 ID 从新到旧核对 URL 路径，避免对捕获内容做关键词扫描。最新匹配连接关闭、初始化不完整或状态无效时直接报错，不继续查找旧连接。

脚本只读取 Reqable 捕获，不发送游戏请求，不消耗传送卡，也不自动点击。JSON 只保留坐标、地块属性、来源记录标识和移动结果，不包含认证 URL、token 或玩家资料。

如果捕获列表没有当前连接的初始化消息，保持捕获开启，返回游戏主页后重新进入大世界。捕获中的移动尚未收到确认、连接已经关闭，或超过 15 秒没有收到任何帧时，脚本报错，不回退到旧连接。

## 自动导航

```bash
python run --navigate 12565 6486 --dry-run
python run --navigate 12565 6486
```

输入游戏顶部展示的坐标。脚本先输出总方向、无障碍距离下限和下一跳，再以“规划一跳、界面点击、确认回包、等待动画、更新地图”的顺序执行。距离下限不是预计实走步数。省略 `--execute` 直接运行底层 `scripts/world_navigation.py` 时也只预检；根目录 `run` 默认开启点击。

NetworkX 优先在已知普通地块上搜索最短路径。没有已知完整路线时，按坐标生成的布局进行有限范围的 A* 预判，将屏幕外和按钮遮挡造成的绕行纳入计算。预判朝目标最多推进 12 格，矩形范围先向四周扩展 2 格；没有候选路线时依次扩大到 4、8、12 格，找到路线即停止扩展。单次决策的预判累计预算为 3000 格，重复搜索的格子计入预算；单级区域最多包含 1369 格。地图边缘裁剪后范围不变的级别跳过。重复经过的地块增加路径代价。更远的目标分段预判，不构造整张世界地图。

预判中的未观测地块只是假设可通行的布局节点，不会写入已知地块集合。下一跳必须已经收到普通地块状态；进入新位置后重新获取周边，奖励、挑战、锁定及未知状态都会改变后续路线。扩展范围或预算耗尽仍无路线、分段目标不可进入、预判下一跳未经确认时，退回已知区域的探索边界选路，允许必要的折返和更大范围绕行。最终目标位置已知但禁止进入时直接停止。

每步日志区分“已知区域最短路”“布局预判，逐步确认”“边界探索”，并显示采用的扩展格数或回退原因。本次 `progress.json` 的 `plan` 字段保留最近一次决策方式、尝试过的扩展级别、累计预判格数及相关参数。未探索区域不能保证可达或全程最短，可能绕行、回退或因没有可达边界而停止。

每次点击须对应当前回包中已确认无活动奖励或挑战的普通相邻地块。成功回包必须与计划目标相符，之后按客户端摄像机动画时长公式等待并再次检查位置。移动确认后清除旧附近礼物状态，等待新推送覆盖当前地块列表，超时停止。该等待是代码计算值，不是视觉识别动画完成；若客户端卡顿导致下次点击未生效，超时停止，不自动重试。任何非预期移动、连接切换、窗口移动或尺寸变化都会停止。鼠标移动和 Ctrl-C 可中断；也可在本次 `runs/navigate-*/` 目录创建 `STOP` 文件。

等待预算从脚本读到成功回包时开始，为 `max(0.6, 1.5 * 地块中心距离 / 900 + 0.15)` 秒。其间等待周边推送，推送读取耗时计入预算，不再串行叠加同等动画等待。预算结束后再次读取当前位置和周边状态；未完成的状态检查不能被时间预算跳过。回包及状态轮询间隔为 0.1 秒，实际步间隔还包含读取、窗口检查和点击耗时。

参数：`--max-steps` 默认 200，范围 1..2000；`--timeout` 默认 10 秒，范围 1..60；`--window-id` 可指定唯一的游戏窗口。达到步数上限时停止，不继续后台移动。重新启动导航从最新确认位置规划，不重放历史点击。

当前仅支持版本 500 对应的等比例 350x665 窗口布局。运行时不自动检测客户端包版本，也不识别游戏内弹窗。请确保游戏停在地区地图且没有弹窗。客户端更新后应重新验证布局，不能将窗口比例检查视为版本兼容性保证。

## 坐标与地块

协议 `Coord` 使用 `x`、`y`。游戏顶部展示的坐标按初始化消息的地图高度换算：

```text
界面 X = 协议 x
界面 Y = mapMaxY - 协议 y
```

`WorldNodeData` 的字段如下：

| 字段号 | 字段 | 含义 |
| --- | --- | --- |
| 1 | nodeCoord | 地块的协议坐标 |
| 2 | province | 地区编号；不是布尔可点击状态 |
| 3 | discovery | 发现事件编号；非零时点击会进入事件处理 |
| 4 | cityId | 城市编号 |

客户端对 `province == 0` 的地块显示锁定背景，且触摸命中检查返回失败。普通移动候选需满足：属于当前位置的相邻地块、不是当前位置、`province > 0`、`discovery == 0`。`terrainMoveCandidate` 只表达这些地形条件；人物状态及服务端规则仍会影响实际移动。`stateAtLogin` 是登录时状态，不是持续更新的人物状态。

岛屿在格子内部有按坐标生成的随机偏移。`world_route.py` 复用 `XorShift128Plus`，按客户端 `initRandom` 和 `resetItemPos` 规则计算地块中心，再以当前位置为摄像机中心换算屏幕坐标。安全点击区域排除顶部栏、边缘和底部操作按钮；不能直接将地区坐标乘固定系数作为点击位置。

## 动态避让

`province` 和 `discovery` 只描述地形，不能判断是否有玩家正在挑战。导航同时合并 Opcode `1120` 的附近礼物全量推送与 `1109` 的单个礼物状态更新；全量推送替换旧集合，增量更新按坐标覆盖。未收到某地块的状态时不将其当成空岛。

| giftState | 枚举 | 导航处理 |
| --- | --- | --- |
| 0 | Invalid | 无 owner 时可作为普通候选 |
| 1 | OwnerLess | 避开未被领取的奖励地块 |
| 2 | Occupied | 避开正在挑战的地块 |
| 3 | Completed | 无 owner 时可作为普通候选 |
| 缺失或其他值 | 未知 | 不进入；等待数据或停止 |

上述数值只有在收到对应礼物消息后才成立；Protobuf 消息内省略 `giftState` 使用默认值 0，不等同于整条礼物消息尚未收到。存在 owner 的异常或未清理状态也保守避开，不依据 `forbidHelp=false` 放行。

输出的 `terrainMoveCandidate` 保留纯地形判断；`giftStatusKnown` 表示已收到该坐标的礼物状态；`navigationBlock` 记录动态避让原因；`navigationCandidate` 才是合并后的下一跳候选。规划更新与点击前检查均使用合并结果。坐标不永久拉黑，后续状态变化会更新判断。

服务端仍可能在最后一次检查与实际点击之间改变状态，客户端无法原子锁定地块；遇到非预期回包或超时停止，不自动开始挑战。

## 协议

| Opcode | 消息 | 用途 |
| --- | --- | --- |
| 1003 | UserLoginNtfInfo | 初始化地图、人物当前位置和地图尺寸 |
| 1100 | UserMoveReqInfo | 指定 `targetCoord` 的移动请求 |
| 1101 | UserMoveAckInfo | 返回 `code`、`mapInfo` 和 `curCoord` |
| 1120 | AllGiftNearByNtfInfo | 周围礼物信息 |
| 1109 | GiftStateChangeNtfInfo | 单个礼物的动态状态变化 |
| 1121 | AllUserNearByNtfInfo | 周围玩家信息 |
| 1335 | UserTeleportAckInfo | 传送结果；读取工具同步其坐标，但不发起传送 |

移动结果 `code`：`0` 成功、`1` 位置错误、`2` 状态错误、`3` 不相邻。Protobuf 可省略默认值，因此成功回包不一定显式包含 `code` 字段。

历史捕获允许多个尚未响应的普通移动请求指向同一目标，按捕获顺序消费对应回包，保留每次成功和失败结果。失败不推进当前位置，也不清除已收到的附近状态。目标不同、移动模式不同、回包缺少请求或仍有未响应请求时停止解析。自动导航期间仍要求每次点击恰好产生一次符合预期的移动结果，额外移动不会被当成正常执行。

客户端二进制帧结构：`02 | opcode（2 字节大端）| 序号（1 字节）| protobuf | CRC32（4 字节小端）`。CRC32 覆盖其前面的全部字节。普通服务端帧为 `序号 | opcode（2 字节大端）| protobuf`；心跳响应 1002 没有序号字节。

复制旧帧会同时复制旧序号和校验值。修改坐标后需要重新计算校验值，序号也必须符合当前连接状态。已有测试只证明正常客户端发送的移动帧可成功，不证明旧帧可在新连接直接重放。
